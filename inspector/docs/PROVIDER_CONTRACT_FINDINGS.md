# Provider contract findings

The Inspector contract in `src/provider/contracts.ts` implements the queries described in architecture §19 while keeping fixture-specific state behind `MockBodyProvider`. These are the places where a browser consumer needs a more explicit response shape than §19 currently specifies. The mock contract makes the gaps visible; it does not define canonical behavior.

1. **Domain presentation kind.** §19 maps `dir_cube` and `radial_1d` to different renderings, but does not name a display-safe discriminator for a consumer. Parsing topology identifiers in the browser would duplicate core interpretation. The prototype receives `DomainDescriptor.renderKind`; consider returning a presentation kind from `domain_geometry()` or the domain descriptor.
2. **Ordered groups.** §19 names `ViewDescriptor.group` / capability `display.group` but does not define group order or a group catalogue. The menu uses `ViewCatalog.groups` with provider-supplied labels and order, then displays each group's declared views. Consider a stable ordered group list in `views()`.
3. **Tile completeness and lifecycle.** §19 describes loading, retry and visible failures, but not typed opening/metadata/view states or partial tile responses. The prototype's `ProviderFailure` carries code, message, optional offending item, category and retryability; `DisplayTile.missingResources` marks partial content. Consider a typed query status/error envelope and a completeness field with missing resource identifiers.
4. **Current display resolution and source.** §19 describes LOD and per-field source/level, but does not specify current-view resolution/source metadata for the status strip. The prototype does not display a canonical LOD or invent a source label; it keeps the persistent synthetic-fixture indicator. Consider returning display resolution and source metadata with the displayed tile if those belong in the Inspector status strip.
5. **Radial profile samples.** §19 requests a profile chart for `radial_profile` but does not specify a query response for chart samples. The mock geometry includes optional provider-supplied profile samples. Consider returning profile samples from `domain_geometry()` or a dedicated profile query.
6. **Diagnostic stage payload.** §19 identifies a Diagnostics group and Stage selector but does not define stage descriptors or the selected snapshot shape. The mock uses ordered `{ id, label }` stages and a display-only snapshot of labeled values. Consider formalizing these shapes in the worker response.
7. **Point position presentation.** §19 specifies `inspect(pos)` and a selected-point block, but not a display-ready position representation. The mock report includes `positionLabel` and `positionValue`, which also support the copy affordance. Consider returning the requested position in a stable inspect result shape, or standardize display formatting from the submitted `pos`.

The view identity, opaque field/derived identifier, operator, label, group, description, time choices, legend mapping, range and statistics follow §19's `ViewDescriptor`/stats direction. Point source kind and level used, explain steps, and provider-resolved feature geometry also follow the described boundary.
