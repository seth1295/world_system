# Conformance corpus

`worlds/` contains committed, deterministic body artifacts. `vectors/canon/` contains identity, codec, and RFC 8785 Appendix B number vectors. `vectors/topology/stage2-parity.json` pins the Stage 2 deterministic seed and native/WASM parity digest. `acceptance/stages-00-03.json` maps foundation requirements to executable evidence. `queries/stage4.jsonl` and `expected/stage4.jsonl` pin sampler, temporal selection, weighted statistics, tile, topology-derived view, and geometry outputs using exact floating-point bit strings.

`veyra-conformance` verifies the addressing, hashing, compatibility, and minimal-void fixtures and runs Stage 4 queries against committed bodies through the core API. `veyra conformance gen` creates missing fixtures and expected output. `veyra conformance verify` compares Stage 4 JSONL results byte-for-byte. `scripts/compare_foundation_wasm.mjs` executes the foundation parity export; `run_wasm_parity.mjs` defines the adapter contract for Stage 4 query parity. Stage 4's CI builds `wasm32-unknown-unknown`, but executable native/WASM sampler parity is not yet verified and remains part of the later application binding work.

`docs/adr/0002-stage4-reduction-and-nodata-rules.md` records the deterministic pyramid and nodata choices. It identifies the unresolved `f32` pyramid conversion rule: V1 permits `f32` rasters while prescribing integer downsample arithmetic, so the current writer refuses to generate `f32` parent tiles.
